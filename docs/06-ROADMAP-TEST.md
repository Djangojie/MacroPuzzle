# 开发路线图与测试计划 v0.2

## 阶段

| 阶段 | 范围 | 完成定义 |
| --- | --- | --- |
| M0 本轮 | 审查参考包、保留原型、建立文档、明确假设与任务 | 文档齐全且交叉一致；明确无新应用源码与自动测试 |
| M1 本机 Web MVP | React/TypeScript + FastAPI/SQLite、SVG 拼图、手动确认记录、演示排序 | `10-PHASE1-TASKS.md` 的 P1-01 至 P1-09 全部验收；只在本机使用 |
| M2 数据与用户验证 | 评估真实营养库许可/地域覆盖、过敏限制、小规模任务观察 | 保留原始观察与失败案例；营养内容经专业复核再用于正式建议 |
| M3 可选联网识别/同步 | 由用户证据触发，单独审查成本、隐私、认证与删除期限 | 用户明确确认后实施；识别只出候选，用户修正后才能记录 |

M1 不接付费 API、账号、生产部署或外部发布。任何营养数据源接入先核查许可、地域适用和更新时间。

## 测试分层

| 层 | 核心风险 | 验收证据 |
| --- | --- | --- |
| TypeScript/Python 纯函数 | 份量、合计、缺失值、目标边界、排序分叉 | 同一 JSON fixture 两端自动通过；未知不被转成 0 |
| FastAPI/SQLite | 写入校验、跨日查询、revision 冲突、幂等、事务 | API 集成测试与临时数据库；写失败不产生半条数据 |
| SVG/UI | 填充与数值不一致、无目标除零、颜色唯一表达 | 组件测试 + 浏览器看 320px/375px/桌面、键盘、读屏文本 |
| 照片与隐私 | 图片意外上传/持久化 | 浏览器网络和 SQLite 检查；取消后 object URL 释放 |
| 用户流程 | 表单确认遗漏、错误后数据丢失 | 手动走通 PRD US-01 至 US-06，记录实际结果 |
| 营养与文案 | 演示值被误解为真实建议、道德化措辞 | 内容审阅；代码测试不等于营养准确性 |

## 发布门槛

M1 的测试通过只证明本机代码路径。公开部署前还需账户/隔离、HTTPS、数据保护与保留策略、真实数据许可、营养专业审阅、目标人群与地区、浏览器兼容性和无障碍检查。本轮不触发发布。
