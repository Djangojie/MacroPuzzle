# PRD v0.1 · 2026-10-15

## 1. 产品定位

MacroPuzzle 把每日饮食记录转成三大营养素拼图，让普通成年人看懂“今天已经记录了什么、下次可怎样搭配”。“薄肌”是一个可研究的兴趣场景，不作为医学或体型承诺。核心体验是记录简单、反馈可解释、语言不羞辱。

### 目标用户和待验证假设

| 人群 | 需求假设 | 验证方式 |
| --- | --- | --- |
| 忙碌的普通成年人 | 比传统卡路里表更易看懂当天营养分布 | 5 人任务观察：不讲解也能解释三色区域 |
| 关注运动与体型的成年人 | 想看餐食怎样影响当日宏量记录 | 5 人访谈：是否愿意连续记录 3 天 |

用户、持续使用动机、市场规模和“会爆”均未验证。首版不宣称促成体型改变。

## 2. MVP 范围

### 必须有

1. **拍照记录**：手机拍照或相册选图，本地预览；用户手动选择/输入食物、份量与营养值，确认后保存文字记录。无图也可记录。图片不自动识别、不上传、不保存。
2. **营养拼图**：同一天所有记录聚合为 P/C/F 三个可视区域，同时给出克数、目标、能量、超额提示和“数值仅估算”说明。历史日期可查看；不在跨日时删除旧记录。
3. **食物推荐**：从明确标为演示数据的有限候选集中，根据缺口排序；显示推荐原因、关键营养值与限制；能一键带入记录表单，但需用户确认。
4. **个人设置**：成年人可手工设目标，预设目标仅作界面演示，首次使用不应误认为个体建议。支持删除本机 API 中的数据。M1 没有账户，仅供本机单用户演示。

### 明确不在第一版

照片自动营养识别、扫码、营养诊断、饮食计划/减重处方、账户、支付、社交、云同步、推送。联网营养库和正式推荐候选清单属第二阶段。M1 不做公开部署。

## 3. 用户故事与验收

| ID | 用户故事 | 可观察验收 |
| --- | --- | --- |
| US-01 | 我拍下或选中午餐，想先看图再决定怎么记 | 手机与桌面可选图；预览有取消；无权限或取消选图仍能手动记 |
| US-02 | 我不确定照片里的重量，想自己修正 | 表单要求份量及来源；保存前展示本次 P/C/F、能量、日期；无效值不能保存 |
| US-03 | 我想看今天还差什么 | 三色区域、数值和文字结论一致；超额单独可见，不被 100% 裁切掩盖 |
| US-04 | 我想知道为何推荐一种食物 | 推荐显示“补充了什么/可能超出什么”和候选来源；完全无合适候选时不强推 |
| US-05 | 我想纠正记录 | 可编辑、删除当天记录并短时撤销；刷新后数据仍在；跨日旧记录可查 |
| US-06 | 我想清除个人数据 | 二次确认后清空本机 API 的记录、目标和当前预览；刷新仍为空 |

## 4. 体验指标（试验目标，非既成事实）

- 5 名目标用户中，至少 4 名能在没有帮助下完成一餐记录并说出推荐理由。
- 记录一餐的中位时间尝试压至 90 秒以内；记录失败或放弃要观察原因。
- 至少 4 名能理解“照片只是辅助”“拼图不等于健康评价”。
- 收集每次推荐“有用/不合适/说不清”及原因；样本小，不推断普遍效果。

## 5. 待确认的产品问题

上线地区、主要食物体系（中国菜/国际）、目标设定是否由营养师审核、未成年人使用政策、数据保留周期、第一版是否只做单机。缺少答案时按“成人、中文、单机演示”实施。
